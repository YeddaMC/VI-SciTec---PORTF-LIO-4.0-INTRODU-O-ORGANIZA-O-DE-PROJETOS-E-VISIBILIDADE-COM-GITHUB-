📚 1. Introdução: O que são o Git e o GitHub?

O GitHub

O GitHub é uma plataforma que permite hospedar, organizar, documentar, compartilhar e colaborar em projetos, inclusive em projetos open source (código aberto), nos quais o código é disponibilizado para que outras pessoas possam conhecer, utilizar, modificar e contribuir com o projeto, de acordo com suas regras de licença e colaboração.

Um dos principais recursos do GitHub são os repositórios, que funcionam como espaços onde um projeto pode ser armazenado, desenvolvido e apresentado. Além de armazenar repositórios, o GitHub oferece recursos para organização, documentação, colaboração, automação e publicação de projetos.

Neste workshop, utilizaremos principalmente:

  • Perfil: conta de usuário na plataforma.
  • Profile README: apresentação personalizada no perfil.
  • Repositório: espaço onde o projeto será armazenado e apresentado.
  • README: apresentação e documentação inicial do projeto.
  • Wiki: documentação complementar.
  • Markdown: formatação dos textos.
  • Links: conexão entre perfil, projeto e documentação.

🛠️ Recursos e Ferramentas Disponíveis na Plataforma

  • GitHub Projects (Kanban): quadros visuais para organizar tarefas, prazos e o fluxo de trabalho de maneira rastreável. As tarefas podem ser criadas e acompanhadas por meio de Issues, atribuídas aos integrantes e visualizadas de diferentes formas, incluindo gráficos.
  • Gerenciamento de Colaboradores: Permite convidar outras pessoas para editar, revisar e construir o projeto juntos.
  • GitHub Actions: automação de fluxos de trabalho, como testes, validações, builds e deploys, sempre que determinados eventos acontecem no projeto (gatilhos).
  • Pipelines e DevOps: Fluxos automatizados que preparam e colocam o sistema para rodar de forma rápida e segura.
  • GitHub Pages (Hospedagem): Publicação gratuita de sites, portfólios e páginas direto a partir dos seus arquivos.
  • GitHub Codespaces (IDE em Nuvem): Um ambiente completo de desenvolvimento que abre no navegador, permitindo criar e testar códigos de qualquer lugar.
  • Gráficos de Linhas de Código (Insights): Painel que mostra estatísticas visuais do projeto, indicando quais arquivos receberam mais atualizações.
  • Métricas de Produtividade (Pulse): Resumo estatístico do ritmo do projeto (tarefas concluídas, pendências e volume de alterações).
  • Contribuição em Projetos Open Source: Permite colaborar diretamente com códigos abertos do mundo inteiro, possibilitando que você aprenda com projetos reais de grandes empresas e desenvolvedores, além de deixar suas próprias contribuições visíveis globalmente.

O Git

O Git é um programa que roda direto no seu computador. Ele funciona como uma máquina do tempo para os arquivos do seu trabalho. Imagine um Trabalho Acadêmico em Equipe: cada vez que você escreve uma seção e salva, o Git cria um Commit (uma foto do estado atual do texto). Se você fizer uma alteração e depois quiser recuperar o código ou o texto anterior, pode olhar os commits antigos e recuperar o arquivo voltando ele ao estado original porque você vai ter “fotos” de todos os diferentes momentos do desenvolvimento.

💡 Nota do Nosso Minicurso: Como o nosso objetivo aqui na VI SciTec é documentar a produção acadêmica diretamente no GitHub, nós não vamos usar o Git no computador hoje, mas é fundamental que você conheça a existência dele e saiba que Git e GitHub não são a mesma coisa.

🔄 GitHub + Git

Como os integrantes e os computadores se comunicam? (Push e Pull)

Para mandar a sua parte do trabalho para a internet, ou trazer a parte que os seus colegas fizeram para o seu computador, você usa dois comandos principais:

  • ⬆️ Push (Empurrar / Enviar): Quando você termina de escrever a metodologia no seu computador e faz o salvamento (commit), essa alteração só existe na sua máquina. Você faz um Push para "empurrar" essa nova seção do seu computador para o GitHub (na internet), deixando-a disponível para o resto do grupo.
  • ⬇️ Pull (Puxar / Trazer): Se um colega de equipe entrou no GitHub e escreveu a conclusão do trabalho, a versão da internet está mais atualizada que a do seu computador. Você faz um Pull para "puxar" a conclusão que ele fez da internet para dentro do arquivo no seu computador.

🏢 Grandes Empresas que Usam o Git e o GitHub: Esta tecnologia não é apenas para estudantes. Ela é o padrão absoluto do mercado global. Gigantes da tecnologia como Microsoft, Google, Meta (Facebook/Instagram), Netflix, Amazon, NASA e Spotify utilizam o Git e o GitHub diariamente para gerenciar seus códigos privados e para disponibilizar seus grandes projetos de código aberto (open source) para a comunidade global. Aprender isso agora é usar a mesma ferramenta que os melhores engenheiros de software do mundo usam.

🕒 Curiosidades

O caos do "Trabalho_Final_Versao99_AgoraVai.docx"

Antes dos sistemas de controle de versão distribuídos, controlar as alterações de um projeto desenvolvido por várias pessoas já era um desafio.

Alguém escrevia a Introdução e mandava por e-mail. Outra pessoa baixava o arquivo, alterava a Metodologia e salvava como Trabalho_Final_V99. Uma terceira pessoa fazia mais algumas alterações e surgia o Trabalho_Definitivo_Atualizado.

No meio de tanta troca, era fácil perder o controle:

  • Qual é o arquivo mais recente?
  • Quem alterou essa parte?
  • Será que alguém sobrescreveu o trabalho da outra pessoa?

Imagine isso acontecendo em uma equipe de desenvolvimento mundial.

Para organizar esse problema, surgiram os sistemas de controle de versão. Entre eles, havia sistemas centralizados, nos quais o projeto ficava associado a um servidor central. Em alguns desses sistemas, um arquivo podia ser bloqueado enquanto uma pessoa trabalhava nele, impedindo alterações simultâneas.

Isso resolvia alguns conflitos, mas também podia criar filas e limitar a forma como as pessoas colaboravam.

Com o surgimento dos sistemas de controle de versão distribuídos (DVCS), o modelo mudou. Em vez de depender exclusivamente de um servidor central, cada participante podia ter uma cópia do repositório e de seu histórico, trabalhar de forma independente e depois sincronizar as alterações.

🐧 E então entra o Linux

É aqui que a história fica interessante.

Em 1991, Linus Torvalds iniciou o desenvolvimento do Linux. O projeto cresceu e passou a receber contribuições de pessoas de diferentes lugares do mundo.

O desenvolvimento do Linux também cresceu rapidamente. Durante seus primeiros anos, de 1991 a 2002, as alterações eram compartilhadas principalmente como patches (arquivos que descreviam as alterações a serem aplicadas ao código) e arquivos compactados.

À medida que o projeto crescia e mais pessoas participavam, tornou-se necessário utilizar ferramentas mais adequadas para controlar e organizar esse desenvolvimento.

🌐 O Linux já usava um sistema distribuído

Em 2002, o projeto do kernel Linux começou a utilizar o BitKeeper, um sistema de controle de versão distribuído (DVCS).

Ou seja: o Git não inventou o conceito de controle de versão distribuído. O BitKeeper já utilizava esse modelo antes do Git existir. A experiência com essa ferramenta também ajudou a mostrar quais características eram importantes para o desenvolvimento de um projeto enorme e distribuído como o Linux.

🍿 E aí a história ficou interessante...

Em 2005, a relação entre a comunidade que desenvolvia o kernel Linux e a empresa responsável pelo BitKeeper se rompeu. Com o fim dessa relação, a autorização que permitia o uso gratuito da ferramenta foi revogada. A documentação oficial do Git descreve o rompimento de forma breve, sem apresentar uma única causa oficial para ele.

O BitKeeper era uma ferramenta proprietária, enquanto o kernel Linux era um projeto de código aberto. Essa diferença fazia parte do contexto da relação entre a ferramenta e a comunidade, mas não é correto reduzi-la, por si só, a uma única causa para o rompimento.

O fato é que a comunidade precisava de outra solução.

Foi nesse contexto que Linus Torvalds e outros desenvolvedores criaram o Git em 2005.

A ideia era desenvolver uma ferramenta que atendesse às necessidades específicas do projeto: ser rápida, simples, totalmente distribuída e capaz de lidar eficientemente com um projeto muito grande, além de oferecer forte suporte ao desenvolvimento não linear, com várias linhas de desenvolvimento acontecendo em paralelo.

O Git também surgiu como uma alternativa livre e de código aberto, adequada ao contexto de desenvolvimento do kernel Linux, aproveitando os aprendizados obtidos com o BitKeeper e com as ferramentas que já existiam.

☁️ E então veio o GitHub

O Git já permitia controlar versões e trabalhar de forma distribuída, mas ainda havia espaço para facilitar o compartilhamento e a colaboração pela web.

Foi nesse contexto que surgiu o GitHub, fundado em 2008.

A plataforma passou a oferecer uma interface web para hospedar repositórios Git, compartilhar projetos, documentar trabalhos e colaborar com outras pessoas.

O próprio GitHub também é desenvolvido usando Git. O primeiro commit no repositório do GitHub foi realizado em 19 de outubro de 2007, antes da fundação da empresa em 2008. O próprio GitHub registrou essa data em seu blog ao completar seu primeiro ano.

Hoje, o GitHub se apresenta como uma plataforma para desenvolver, compartilhar e colaborar em projetos de software, com a comunidade open source como uma parte importante de seu ecossistema.

📝 3. O Nosso Foco Hoje: Ecossistema de Portfólio Integrado

Nesta oficina, pularemos os comandos complexos de terminal de computador. Entraremos direto no site do GitHub para construir um ecossistema conectado.

Perfil → Portfólio → Repositórios de projetos → Markdown.

  • Perfil (A Porta de Entrada): É a sua página principal no GitHub e funciona como um cartão de visitas profissional. Nela, você pode apresentar quem você é, seus interesses e objetivos, além de adicionar links para o LinkedIn, site, portfólio e outros projetos. Neste workshop, vamos personalizar o perfil por meio do Profile README, criando uma apresentação que poderá direcionar para seus projetos e portfólio.
  • Repositório de Portfólio (O Acervo de Projetos): Um repositório criado para organizar e apresentar os seus projetos. Nele, você pode reunir links para os diferentes repositórios de trabalhos que deseja destacar, organizando-os no README de acordo com a sua preferência, inclusive em ordem cronológica.
  • Repositório de Projeto: É o espaço destinado a armazenar, desenvolver, documentar e apresentar um projeto específico. Pode ser utilizado para projetos acadêmicos ou pessoais e pode ser público ou privado, de acordo com a finalidade do projeto e as configurações escolhidas pelo usuário.
  • Markdown (A Formatação): É uma linguagem simples de formatação de textos que utiliza símbolos para estruturar e formatar o conteúdo, como ## Título para criar um subtítulo ou [Texto do link](endereço) para inserir um link. Quem já aprendeu HTML perceberá que o Markdown possui uma função semelhante de estruturar e formatar conteúdos, mas utiliza uma sintaxe diferente. Não é necessário saber HTML ou Markdown para realizar esta atividade: podemos transformar textos em Markdown rapidamente com a ajuda da IA e, depois, revisar o resultado.
